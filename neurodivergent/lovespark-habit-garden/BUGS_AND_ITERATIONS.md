# LoveSpark Habit Garden - Bugs and Iterations

## v1.0.0 (2026-03-21) - Initial Build

### Architecture Decisions
- **storage + alarms only** - Simplest possible permission surface. No content scripts, no host permissions.
- **Plant growth stages** - 6 stages based on streak length: Seed (0), Sprout (1-2), Seedling (3-6), Flower (7-13), Blossom (14-29), Tree (30+)
- **Daily reset via alarm** - Hourly alarm checks for day change. Streak breaks if yesterday wasn't completed.
- **Max 12 habits** - Prevents grid overflow in popup. V2 could add scrolling/pagination.
- **DOM API only** - el() helper for building cards. Zero innerHTML per KI-011.

## 2026-07-08: ITER-CWS-A11Y-1 — beige-theme contrast fail on delete-icon hover opacity

**Problem:** `ls-check .` flagged A11Y-KI004 — `.habit-card:hover .card-delete` used `opacity: 0.6`, which drops below the 4.5:1 contrast floor on the beige theme (KI-004).
**Root cause:** Opacity-based dimming instead of a full-opacity muted color; beige's base contrast is thinner than retro/dark/slate so the same opacity value that reads fine elsewhere fails there.
**Fix:** Raised `.card-delete` hover opacity to 0.85 per the documented KI-004 fix path (opacity ≥ 0.85 on beige-theme text/icons). No functional change, no other themes affected. `ls-check .` unchanged at 0 fail; confirmed the specific KI-004 warning is gone.
**Files:** popup.css, manifest.json (1.0.32 → 1.0.33)

## 2026-07-08: ITER-CWS-A11Y-2 — A11Y-CONTRAST fail is a canonical shared-lib defect, not fixable in this repo

**Problem:** `ls-check .` reports `A11Y-CONTRAST: Contrast audit: 3 failure(s)` — `[beige] Hint text (0.8 opacity) on glass: 4.26:1 (needs 4.5:1)`, `[slate] Muted text on glass-strong: 4.17:1 (needs 4.5:1)`, `[slate] Slider thumb on track: 2.65:1 (needs 3.0:1)` — identically across every extension in the neurodivergent batch (habit-garden, hub, med-tracker, tab-garden, mood-bloom, context-switch all show the exact same 3 failures/ratios).
**Root cause:** `audit-contrast.py` (invoked by `ls-check.py`'s A11Y-CONTRAST check) resolves the shared-lib token file via `find_shared_lib()`, which walks up from **the audit script's own file location** (`Claude x LoveSpark/scripts/`), not from the repo path passed on the command line. It therefore always audits the canonical `Extensions/infrastructure/lovespark-shared-lib/lovespark-tokens.css` regardless of which repo `ls-check .` is run against. These 3 failures are already documented as known issues (KI-002, KI-003, KI-004 in `~/.claude/docs/memory/known-issues.md`) with real, computed fixes — but the fix must land in the canonical token source, not in any single extension's own `lib/` copy (editing the per-repo copy would only desync it from canonical and trip the separate "shared lib matches canonical" check).
**Fix (verified, ready to apply by whoever owns `lovespark-shared-lib` / `design-tokens`):** In `design-tokens/tokens.json` primitives — darken `earth-dark` from `#5C4A2A` to `#4E3F24` (beige `text.dark`, fixes the 0.8-opacity hint-text check to 4.87:1, all other beige pairings re-verified passing with margin); lighten `gray-muted` from `#9A9A9A` to `#A5A5A5` (slate `text.muted`, fixes muted-on-glass-strong to 4.76:1); add a new primitive `rust-focus: #DA8763` and repoint slate's `interactive.focus-ring` to `{rust-focus}` instead of `{rust}` (fixes slider-thumb-on-track to 3.22:1) — this decouples the focus-ring fix from `rust`, which is also slate's decorative pink-accent and title-override color, so those stay visually unchanged. Verified via `generate-tokens.py --check`: 28/28 contrast pairings pass, 0 regressions. After landing, regenerate `lovespark-tokens.css`/`LoveSparkTokens.swift`, sync to all extensions via `scripts/sync-shared-lib.sh`, and re-run `ls-check .` fleet-wide.
**Why not fixed here:** `lovespark-shared-lib` and `design-tokens` are not part of this repo; per the fleet-p1 unit's scope discipline (assigned repos only, never touch other repos), the canonical-infra fix was computed and verified but not applied — flagged as a follow-up task instead.
**Files:** none (documentation only — no in-repo fix exists for this failure)

## 2026-10-07: BUG-001 — committed store zips recursively embedded the previous store zips (10.2 MB each)

**Problem:** PR #1's `lovespark-habit-garden-chrome.zip` / `-firefox.zip` (v1.0.34) were 10,246,454 / 10,246,641 bytes — vs 170,071 bytes on `main` (v1.0.0). `unzip -l` showed each zip contained `lovespark-habit-garden-chrome.zip` (4,488,546 B) and `lovespark-habit-garden-firefox.zip` (4,488,733 B), and those nested zips (v1.0.33) in turn contained the v1.0.32 zips (1.6 MB each). Every rebuild roughly doubled the package. Uploading this to CWS/AMO would ship ~9 MB of stale nested archives to users.
**Root cause:** `scripts/build-zips.sh` stages the extension dir with `rsync` and an explicit exclude list (`.git/`, `cws-shots/`, `BUGS_AND_ITERATIONS.md`, ...) — but `*.zip` is not on that list, and this repo commits its store zips at the root. So each build zipped the previous build's zips. The script honors a per-extension `.zipignore` (`--exclude-from`), which this repo did not have.
**Fix:** Added `.zipignore` containing `*.zip`. Rebuilt both zips via the canonical `build-zips.sh` (unchanged script; output dir redirected to a scratch folder): 1,268,785 / 1,268,972 bytes, 83 files each (85 - 2 nested zips), no `.zip` entries inside, manifest 1.0.35, Firefox zip `amo-validate.py` clean. Bumped manifest 1.0.34 -> 1.0.35.
**Regression check (no test harness in this repo; run after every `build-zips.sh`):** `for z in chrome firefox; do unzip -l lovespark-habit-garden-$z.zip | grep -v '^Archive:' | grep -c '\.zip$'; done` must print `0` twice.
**Follow-up (fleet-level, not this repo):** add `--exclude '*.zip'` to the canonical `scripts/build-zips.sh` so every extension that commits its zips at the root is protected without a per-repo `.zipignore`.
**Files:** .zipignore, manifest.json (1.0.34 -> 1.0.35), CHANGELOG.md, lovespark-habit-garden-chrome.zip, lovespark-habit-garden-firefox.zip

## 2026-10-07: BUG-002 — public store zips shipped submission docs with `/Users/` home paths

**Problem:** The v1.0.35 `lovespark-habit-garden-chrome.zip` / `-firefox.zip` (83 entries each) — the packages uploaded publicly to CWS/AMO, downloadable by anyone — contained `SUBMIT.md`, `CWS-LISTING.md`, `cws-listing.json`, `PRIVACY.md`, `README.md` and `screenshots/`. `unzip -p lovespark-habit-garden-chrome.zip SUBMIT.md | grep -c /Users/` printed `5` for each zip (local upload paths under `~/...`). The `main` v1.0.0 zip held runtime files only, so this was a regression from the ITER-CWS-01 bundle commit. Found by the PR #1 skeptic pass.
**Root cause:** `build-zips.sh`'s built-in exclude list covers `cws-shots/`, `BUGS_AND_ITERATIONS.md`, `CHANGELOG.md` but not the other submission-bundle files that ITER-CWS-01 committed at the repo root, and this repo's `.zipignore` only listed `*.zip`.
**Fix:** Appended `SUBMIT.md`, `CWS-LISTING.md`, `cws-listing.json`, `PRIVACY.md`, `README.md`, `screenshots/`, `cws-shots/` to `.zipignore` (no runtime file references any of them — grep of *.js/*.html/*.json/*.css). `LICENSE` stays in the package (MIT notice). Rebuilt both zips via canonical `build-zips.sh`: 75 entries each, manifest 1.0.36, Firefox zip `amo-validate.py` PASS, `ls-check .` 35 pass / 0 fail.
**Regression check (no test harness; run after every `build-zips.sh`):**
`for z in chrome firefox; do d=$(mktemp -d); unzip -q lovespark-habit-garden-$z.zip -d $d; echo "$z: $(grep -rl /Users/ $d | wc -l) home-path files, $(unzip -Z1 lovespark-habit-garden-$z.zip | grep -cE '\.(md|zip)$|screenshots/|cws-') non-runtime entries"; done` must print `0` / `0` for both.
**Follow-up (fleet-level, not this repo):** canonical `scripts/build-zips.sh` should exclude `SUBMIT.md`, `CWS-LISTING.md`, `cws-listing.json`, `PRIVACY.md`, `screenshots/` and fail on any `/Users/` string in the staged tree, so every extension carrying the CWS bundle is protected.
**Files:** .zipignore, manifest.json (1.0.35 -> 1.0.36), CHANGELOG.md, lovespark-habit-garden-chrome.zip, lovespark-habit-garden-firefox.zip
