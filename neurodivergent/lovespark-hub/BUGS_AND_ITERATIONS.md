## 2026-07-08: ITER-CWS-A11Y-1 — beige contrast fail, missing sendMessage error handling, missing README/LICENSE

**Problem:** `ls-check .` flagged three real issues: (1) A11Y-KI004 — `.task-item.done` used `opacity: 0.45`, below the 4.5:1 floor on the beige theme; (2) SEC-SENDMSG — the reminder "mark done" `chrome.runtime.sendMessage` call in newtab.js had no error handling, so a torn-down extension context (e.g. mid-reload) would throw uncaught; (3) QUAL-README/QUAL-LICENSE — both files were missing from the repo root.
**Root cause:** (1) opacity-based dimming without checking beige contrast (KI-004 pattern); (2) sendMessage call written before KI-031 (sendMessage try/catch) was adopted fleet-wide; (3) repo scaffolded before README/LICENSE were made mandatory scaffold outputs.
**Fix:** Raised `.task-item.done` opacity to 0.85. Wrapped the sendMessage call in try/catch, plus a `chrome.runtime.lastError` check in its callback, matching the KI-031 pattern used elsewhere in the fleet. Added README.md (pulled from manifest.json description) and the standard MIT LICENSE (matches every other LoveSpark repo). `ls-check . --strict` improved from 5 fail to 1 fail (remaining: MV3-STORAGE-KEY, a checker false positive — see repo-wide note below).
**Files:** newtab.css, newtab.js, README.md, LICENSE, manifest.json (1.0.30 → 1.0.31)
**Note on MV3-STORAGE-KEY:** `lib/lovespark-theme.js` sets the theme key via `chrome.storage.local.set({ theme })` (ES6 shorthand property). The checker's regex only matches explicit `key: value` colon syntax, so it misreports "theme" as read-but-never-set. Verified by inspection — not a real bug. Not fixed because the file is the canonical shared-lib copy (must byte-match `Extensions/infrastructure/lovespark-shared-lib/`); forking it to satisfy a checker regex would break the BRAND "Shared lib matches canonical" check instead.

## 2026-07-08: ITER-CWS-A11Y-2 — A11Y-CONTRAST fail is a canonical shared-lib defect, not fixable in this repo

**Problem:** `ls-check .` reports `A11Y-CONTRAST: Contrast audit: 3 failure(s)` — `[beige] Hint text (0.8 opacity) on glass: 4.26:1 (needs 4.5:1)`, `[slate] Muted text on glass-strong: 4.17:1 (needs 4.5:1)`, `[slate] Slider thumb on track: 2.65:1 (needs 3.0:1)` — identically across every extension in the neurodivergent batch (habit-garden, hub, med-tracker, tab-garden, mood-bloom, context-switch all show the exact same 3 failures/ratios).
**Root cause:** `audit-contrast.py` (invoked by `ls-check.py`'s A11Y-CONTRAST check) resolves the shared-lib token file via `find_shared_lib()`, which walks up from **the audit script's own file location** (`Claude x LoveSpark/scripts/`), not from the repo path passed on the command line. It therefore always audits the canonical `Extensions/infrastructure/lovespark-shared-lib/lovespark-tokens.css` regardless of which repo `ls-check .` is run against. These 3 failures are already documented as known issues (KI-002, KI-003, KI-004 in `~/.claude/docs/memory/known-issues.md`) with real, computed fixes — but the fix must land in the canonical token source, not in any single extension's own `lib/` copy (editing the per-repo copy would only desync it from canonical and trip the separate "shared lib matches canonical" check).
**Fix (verified, ready to apply by whoever owns `lovespark-shared-lib` / `design-tokens`):** In `design-tokens/tokens.json` primitives — darken `earth-dark` from `#5C4A2A` to `#4E3F24` (beige `text.dark`, fixes the 0.8-opacity hint-text check to 4.87:1, all other beige pairings re-verified passing with margin); lighten `gray-muted` from `#9A9A9A` to `#A5A5A5` (slate `text.muted`, fixes muted-on-glass-strong to 4.76:1); add a new primitive `rust-focus: #DA8763` and repoint slate's `interactive.focus-ring` to `{rust-focus}` instead of `{rust}` (fixes slider-thumb-on-track to 3.22:1) — this decouples the focus-ring fix from `rust`, which is also slate's decorative pink-accent and title-override color, so those stay visually unchanged. Verified via `generate-tokens.py --check`: 28/28 contrast pairings pass, 0 regressions. After landing, regenerate `lovespark-tokens.css`/`LoveSparkTokens.swift`, sync to all extensions via `scripts/sync-shared-lib.sh`, and re-run `ls-check .` fleet-wide.
**Why not fixed here:** `lovespark-shared-lib` and `design-tokens` are not part of this repo; per the fleet-p1 unit's scope discipline (assigned repos only, never touch other repos), the canonical-infra fix was computed and verified but not applied — flagged as a follow-up task instead.
**Files:** none (documentation only — no in-repo fix exists for this failure)

## 2026-07-08: ITER-CWS-A11Y-3 — Google Fonts CDN links in newtab.html (SEC-CDN-FONTS)

**Problem:** `ls-check .` flagged SEC-CDN-FONTS — `newtab.html` loaded DM Mono + Press Start 2P from `fonts.googleapis.com`/`fonts.gstatic.com` via `<link>` tags (a live external network request every time the extension's new-tab page opens), violating the privacy-first/no-external-requests rule (KI-026).
**Root cause:** This repo predates the fleet's move to bundling fonts locally; it never got the `lib/lovespark-fonts.css` + `lib/fonts/*.woff2` sync that other extensions (e.g. habit-garden) already received.
**Fix:** Copied the canonical `lovespark-fonts.css` (54 `@font-face` rules covering all 4 themes' font families) and its 51 `.woff2` files from `Extensions/infrastructure/lovespark-shared-lib/` into `lib/`. Replaced the two `<link rel="preconnect">` tags and the Google Fonts stylesheet `<link>` in `newtab.html` with a single local `<link rel="stylesheet" href="lib/lovespark-fonts.css">`. No visual change — same font families/weights, now served from the bundled extension instead of a live CDN request. `ls-check .` SEC-CDN-FONTS went from fail to pass.
**Files:** newtab.html, lib/lovespark-fonts.css (new), lib/fonts/*.woff2 (new, 51 files), manifest.json (1.0.31 → 1.0.32)
