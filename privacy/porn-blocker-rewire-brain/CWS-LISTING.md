## 6. Permission justifications (CWS Section 5 — required text)

Paste these verbatim into the CWS Developer Dashboard permission justification
fields. Each is concise, accurate, and tied to a single concrete feature.

### `storage`

```
Stores user settings (image blur on/off, sensitivity, theme), streak data
(sobriety start date, daily milestone progress, XP level), and journal
entries locally via chrome.storage.local. No remote storage. No sync.
Required to remember the user's recovery progress across browser sessions.
```

### `declarativeNetRequest`

```
Blocks 125+ adult websites at Chrome's network layer using static rules
defined in rules.json. Uses Chrome's declarative API so no browsing data
ever passes through the extension — the browser enforces the blocks
directly. This is the single-purpose feature: blocking explicit content.
```

### `declarativeNetRequestWithHostAccess`

```
Required to add user-defined custom domains and subreddits to the blocklist
at runtime via the settings page. Without this permission, users could not
add their own domains to block. The dynamic rules use the same browser-
enforced declarative mechanism — no browsing data passes through the
extension.
```

### `tabs`

```
Used to open the dashboard page and the first-install onboarding page in a
new tab via chrome.tabs.create(). Required to provide the full-screen
sobriety dashboard experience. The extension does not read tab URLs or
content for any other purpose.
```

### `alarms`

```
Used for two purposes:
1. Hourly dailyStreak alarm — updates the user's streak day count and XP
   reliably even when the service worker is suspended (MV3 requirement).
2. Optional daily journal reminder — fires at the user-selected time
   (default 21:00) to remind the user to reflect on their day.
Both alarms run entirely locally; no network calls.
```

### `notifications`

```
Fires the optional daily journal reminder notification at the user-selected
time. The user explicitly opts in during onboarding and can disable it
anytime. The notification is purely informational ("Time to reflect on
your day") — it does not include any user data and no data is sent
externally.
```

### Host permissions justification (`<all_urls>`)

```
The image-blur feature inspects images on every page the user visits to
classify NSFW content on-device using a bundled TensorFlow.js MobileNetV2
model. The classifier runs entirely in the user's browser — no image data,
URLs, or browsing activity is ever transmitted to any server. The
<all_urls> match is necessary because explicit images can appear on any
website (search engines, social media, image hosts, blogs). Limiting host
permissions to a specific list would defeat the safety net's purpose.

The extension does NOT:
  - Read page text or DOM beyond image elements
  - Track navigation between pages
  - Send any data externally
  - Inject any tracking scripts
  - Modify page content except by adding CSS classes to blur explicit images
```
