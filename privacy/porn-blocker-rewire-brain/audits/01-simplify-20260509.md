## Summary

The codebase is in good shape but carries a small layer of vestigial state and helpers from earlier iterations. Most cruft falls into three buckets:

1. **Unused helpers** (3 functions never called)
2. **Vestigial storage fields** (4 fields written but never read by any UI)
3. **Duplicated literals** (built-in domain/subreddit list mirrors `rules.json`; milestone array literal duplicated between `xp.js` and `background.js`)

Total deletable: roughly 80–110 lines without changing behavior. Risk is uniformly low because the items are either zero-reference or simple constant deduplications.

## Opportunities

### 1. Unused helpers

#### 1a. `escHtml` in `options.js:295-299`
- **What:** Three-line helper that escapes a string via DOM. Called nowhere.
- **Why it's dead:** Every value in this file is rendered with `textContent` or `appendChild(document.createTextNode(...))`, so escaping is already done by the DOM. `escHtml` is a holdover from an earlier `innerHTML`-based render.
- **Lines saved:** 5
- **Risk:** low

#### 1b. `checkMilestoneBonus` in `xp.js:103-114`
- **What:** Returns the milestone day a streak just crossed.
- **Why it's dead:** No consumer. `background.js:418-430` re-implements the same logic inline (against a locally-redeclared `BONUS_DAYS`). Either delete this helper or use it from background.
- **Lines saved:** 11 (helper) + the duplicated `BONUS_DAYS` literal in background can read the canonical `MILESTONE_BONUS_DAYS` from `xp.js` (background already loads it as a service-worker import is not configured here, so simpler fix is just delete the unused helper).
- **Risk:** low

#### 1c. `getResourcesByCategory` in `resources.js:114-118`
- **What:** Returns `RESOURCES[category]`.
- **Why it's dead:** Every consumer reads `RESOURCES[key]` directly (`popup.js:232`, `blocked.js:155-159`). Single-line wrapper used zero times.
- **Lines saved:** 8
- **Risk:** low

### 2. Vestigial storage fields

#### 2a. `totalBlocksEver` (background.js:25, 147, 150, 156, 299)
- **What:** Mirror of `blockedCount` that survives `RESET_STATS`. Written on every block.
- **Why it's dead:** No UI reads it. The only divergence from `blockedCount` is that reset zeroes both anyway (line 299). The "total ever" semantics are unused.
- **Lines saved:** 5 lines + one storage field
- **Risk:** low (but if you want lifetime tracking, leave it — flag if there's a planned UI surface)

#### 2b. `breathingCompleted` (background.js:26, 300, 355-359)
- **What:** Counter of completed breathing exercises.
- **Why it's dead:** Written on `BREATHING_COMPLETED` message, never read by any UI. Returned in the response but no caller uses the value (`blocked.js:81-83` only checks `!res.error`).
- **Lines saved:** ~6 lines + one storage field, and message handler stops fetching `breathingCompleted` from storage
- **Risk:** low

#### 2c. `pauseMinutes` (background.js:19, 91, 247, 259)
- **What:** Stores the requested pause duration alongside `pauseUntil`.
- **Why it's dead:** Only `pauseUntil` is ever consumed (`popup.js:83-87`). `pauseMinutes` is set/cleared in three places but never read. Either drop it or use it (e.g. show "paused for 15 min" on toggle).
- **Lines saved:** 4 lines + one storage field
- **Risk:** low

#### 2d. `streakStartDate` in the `SITE_BLOCKED` storage.get (background.js:146)
- **What:** Field is fetched but never read inside that case (`updates.streakStartDate = today` at line 162 only writes).
- **Why it's dead:** Misreading the original gap-check intent left an unused fetch. Removing it from the get list is purely cosmetic but signals intent.
- **Lines saved:** 1 token (one entry in the array)
- **Risk:** low

#### 2e. Onboarding `goal` and `journalTime` carry-overs (onboarding.js:13-16, background.js:340-349)
- **What:** Onboarding sends `goal: ''` and `journalTime: ''` although the current onboarding HTML only collects `reason`. The dashboard `motivGoal` block (dashboard.js:88-92, dashboard.html:577-579) only fires when `userGoal` is truthy, which it can never be.
- **Why it's vestigial:** Onboarding was simplified to one question; the goal/journal-time fields, `userGoal` storage, and the dashboard motivGoal block are leftovers from the longer flow.
- **Lines saved:** ~10 lines across onboarding.js (4), background.js (4), dashboard.js (5), and ~3 lines of dashboard.html
- **Risk:** low — but if you plan to re-introduce a multi-step onboarding (ROADMAP indicates none currently), keep.

### 3. Duplicated literals

#### 3a. `BONUS_DAYS` redeclared in `background.js:422`
- **What:** `[7, 14, 30, 60, 90, 180, 365]` is declared in `xp.js:31` as `MILESTONE_BONUS_DAYS` and again inside the streak loop.
- **Why duplicated:** The service worker cannot share modules with `xp.js` (xp.js is a classic script for the popup/dashboard, not imported by the SW). Either:
  - **Inline option:** keep both literals; add a comment in `background.js` pointing to `xp.js` for the canonical list.
  - **Refactor option:** convert to ESM and use `importScripts('xp.js')` in the SW. Bigger change; not worth it for one 7-element array.
- **Recommendation:** add a one-line comment, no code change.
- **Lines saved:** 0 (annotation only)
- **Risk:** none

#### 3b. `BUILTIN_DOMAINS` (background.js:504-533) and `BUILTIN_REDDIT_SUBS` (535-543) mirror `rules.json`
- **What:** ~110 hardcoded domains in JS and another 156 entries in `rules.json`.
- **Why it exists:** `isUrlBlocked()` is a content-script fallback for cases where DNR redirect didn't fire (e.g. SPA route changes that don't trigger main_frame nav). The DNR rules can't be queried at runtime, so the list is mirrored.
- **Status:** This is genuine defense-in-depth, not over-engineering — DNR has known gaps with same-origin client-side routing. Keep.
- **Possible improvement:** generate `BUILTIN_DOMAINS` from `rules.json` at build time via a `scripts/sync-blocklist.js` step. Not in scope for this audit; flag for ROADMAP if double-maintenance becomes a problem.
- **Lines saved:** 0 right now (build-time codegen would save sync burden, not lines)
- **Risk:** none today

### 4. Over-engineered safeguards

#### 4a. `content.js` 500ms unhide safety timeout (content.js:49-51)
- **What:** Worst-case fallback to remove the visibility-hidden CSS in case the SW never replies.
- **Status:** This is real defense — MV3 service workers genuinely sleep and can take 200–800ms to wake. The 500ms is justified. Keep.
- **Lines saved:** 0
- **Risk:** none (removing this would break first-block UX after SW idle)

#### 4b. `chrome.alarms.get('dailyStreak', ...)` guard on init (background.js:83-85)
- **What:** Avoids re-creating an existing alarm when the SW restarts.
- **Status:** Documented MV3 best practice. `chrome.alarms.create` would replace, but the guard keeps the next-fire timestamp stable across restarts. Keep.

#### 4c. `chrome.declarativeNetRequest.onRuleMatchedDebug` (background.js:607-610)
- **What:** Console-logs every matched rule. Only available with `--enable-extensions-debug-mode`.
- **Status:** dev-only listener that's harmless in prod (the `?.addListener?.` chain no-ops in stable Chrome). Keep, or move behind an `if (DEBUG)` flag if you want to be cleaner. Leans cosmetic.
- **Lines saved:** 4 if removed
- **Risk:** low — losing debug helper
